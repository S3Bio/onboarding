17  Julia for Data Analysis

In the S3Bio lab, our data analysis workflow is a systematic process built on the JuliaStats and Tidier.jl ecosystems. This chapter breaks down our best practices across the five core stages of research analysis.

17.1 Data Collection & Import

We use TidierFiles.jl for a Tidyverse-consistent data import experience.

17.1.1 Best Practices

  • Standardized Inputs: Prefer CSV or Arrow formats for tabular data.
  • Remote Data: If your data is hosted online, use download() before reading.
  • Lab Rule: Always read data as a DataFrame to ensure compatibility with our Tidy tools.
using Tidier, StatsKit

# Importing from a local CSV
df_raw = read_csv("data/raw_experiment_data.csv")

17.2 Data Preprocessing & Cleaning

Data cleaning is the most critical step for reproducibility. We use TidierData.jl to create clear, auditable cleaning pipelines.

17.2.1 Best Practices

  • Handle Missing Values: Explicitly deal with missing values using @filter(!ismissing(col)) or imputation.
  • Type Conversion: Ensure columns have correct types (e.g., categorical for genotypes).
  • Normalization: Perform all scaling and normalization within the cleaning pipeline.
df_clean = @chain df_raw begin
    @filter(!ismissing(quality))
    @mutate(genotype = categorical(genotype))
    @mutate(value_norm = (value - mean(value)) / std(value))
end

17.3 Exploratory Data Analysis (EDA)

EDA allows us to understand the distributions and relationships in our data before formal modeling.

17.3.1 Best Practices

  • Summarization: Use @group_by and @summarize to calculate key metrics.
  • Quick Visualization: Use TidierPlots.jl to spot outliers or trends.
# Summarizing by group
summary_stats = @chain df_clean begin
    @group_by(genotype, treatment)
    @summarize(mean_val = mean(value_norm), n = n())
end

# Quick EDA plot
df_clean |>
    ggplot(aes(x = :value_norm, fill = :genotype)) +
    geom_density(alpha = 0.5)

17.4 Statistical Analysis

For formal hypothesis testing and modeling, we transition to the robust JuliaStats ecosystem, primarily GLM.jl and MixedModels.jl.

17.4.1 Best Practices

  • Model Choice: Use lm() for simple linear models and lme() for mixed-effects models (when you have biological replicates).
  • Inference: Always report effect sizes and confidence intervals, not just p-values.
# Fitting a Linear Model
model = lm(@formula(value_norm ~ genotype * treatment), df_clean)

# Inspecting results
println(coeftable(model))
println("R²: ", r2(model))

17.5 Data Presentation

Presentation-quality figures and tables are the final output of our workflow.

17.5.1 Best Practices

  • Layered Graphics: Build complex plots layer-by-layer using TidierPlots.jl.
  • Theming: Use consistent themes (e.g., theme_minimal()) and lab-standard color palettes.
  • Exporting: Save figures as vector graphics (.pdf or .svg) for publication.
final_plot = df_clean |>
    ggplot(aes(x = :genotype, y = :value_norm, color = :treatment)) +
    geom_boxplot(outlier_shape = NA) +
    geom_jitter(width = 0.2, alpha = 0.5) +
    labs(
        title = "Impact of Treatment across Genotypes",
        subtitle = "n = 3 biological replicates",
        x = "Genotype",
        y = "Normalized Expression (Z-score)"
    ) +
    theme_minimal()

# Save for publication
# ggsave("results/figure1.svg", final_plot)

17.6 Compliance with Reproducible Research Rules

To ensure your Julia analysis is fully reproducible and compliant with Lab Rules, you must follow these technical requirements:

  • Environment Lockdown: Always include Project.toml and Manifest.toml. This ensures that anyone else can run your analysis with the exact same package versions.
  • No Absolute Paths: Use the data/ directory relative to your project root. Never use paths like C:/Users/....
  • Scripted Analysis: Every result must be generated by code within your Quarto document. Avoid “manual” steps in the REPL that are not recorded in the script.
  • Seed for Randomness: If your analysis involves random sampling or simulations, always set a seed using Random.seed!(123) for deterministic results.
  • Version Control: Commit your .qmd files and helper scripts to GitHub. Do not commit large datasets (use the lab’s shared drive instead).
